# Changelog

- **2026-08-08 - Alan Code 1.3.0**
  - Hardened offline and slow-endpoint operation: package import selects LiteLLM's packaged cost metadata before any backend is loaded; both LiteLLM and Anthropic custom endpoints get one-hour automatic timeouts; explicit `request_timeout`/`--request-timeout`, SimpleLM `max_model_len` discovery, and retry classification cover pre-content timeouts, connection failures, and HTTP 5xx responses.
  - Completed native streamed tool-call assembly and text-tool parsing from visible or reasoning content. Malformed native tool arguments receive bounded correction feedback, persistent opaque 5xx failures get one emergency-compaction attempt, and reasoning-only/empty completions surface an `empty_response` error instead of silently ending a turn.
  - Renamed internal transport APIs, modules, files, settings, and documentation consistently around `backend`, while removing obsolete GUI, REPL, and session complexity.
  - Added backend lifecycle cleanup, the `context_window` property and `--cw` override, transactional live backend changes, and lock-backed updates for project settings, permission rules, and the shared context-window cache.
  - Made `append_system_prompt` a working constructor/settings option for framework-specific instructions after Alan's normal prompt, tightened silent exception handling and local imports, and synchronized the documentation with the 1.3 code.
- **2026-07-25 - Alan Code 1.2.0**
  - Reworked context budgeting around each model's usable input space. Output reservations are clamped before every call, and local or otherwise unknown models can resolve their context window from registry data, server metadata, a cached probe, or an explicit override.
  - Made long sessions resilient: tool outputs use context-scaled caps, compaction retries prompt-too-long failures, and a deterministic hard-truncation fallback preserves a valid recent conversation when summarization cannot fit or repeatedly fails. Fixes [#2](https://github.com/tboulet/Alan-Code-agent/issues/2).
  - Preserved valid tool-call history when a turn is interrupted by synthesizing error results for calls that did not complete.
  - Fixed model-invoked skill tool restrictions, text tool-call parsing, system-prompt consistency, GUI/API event handling, and several small-context-window edge cases.
- **2026-05-11** — Added a remote-controlled scripted backend. Selected via `--backend scripted --model remote` (or in Python: `AlanCodeAgent(backend="scripted", model="remote")`). The backend hosts a small HTTP server on `127.0.0.1:8430+` (port chosen at startup) and blocks each LLM call until an external caller posts a response. Endpoints: `GET /api/health`, `GET /api/session`, `GET /api/pending`, `POST /api/respond`. The pending payload is also mirrored to `<cwd>/.alan/sessions/<sid>/remote_inbox.json` for easy inspection. Lets a human (or another agent) impersonate the model end-to-end for debugging tool wiring, system prompts, or framework integrations. See [docs/guides/remote-scripted-backend.md](docs/guides/remote-scripted-backend.md).
- **2026-05-11** - Backend / model UX redesign. `--backend` selects `auto`, `anthropic-native`, or `scripted` and is inferred from `--model` when omitted. A bare Claude name picks `anthropic-native`; other model names use LiteLLM through `auto`.
- **2026-05-07** — Added `programmatic=True` mode to `AlanCodeAgent` for embedding Alan as a library in benchmark harnesses, parent agents, and unattended pipelines. Skips project/global instructions and memory, plus the `WebFetch`/`GitCommit`/`AskUserQuestion`/`Skill` tools. New `tools=` and `disabled_tools=` constructor params for fine-grained tool control.
- **2026-05-07** — `SessionState` now takes an exclusive `flock` on `<session_dir>/session.lock`. Two processes loading the same `session_id` would otherwise stomp each other's writes; the second now raises `alancode.session.SessionLockedError`. Released by `agent.close()` and on process exit.
- **2026-05-07** — Added `gui_label` parameter to `AlanCodeAgent`, overriding the URL path segment for the GUI bridge.
- **2026-04-28** — Restructured system prompt for caching. `session_guidance`, `scratchpad`, and `environment` are now in the cacheable static block. Removed `git status` from the system prompt (it changed every turn and killed the cache).
- **2026-04-28** — Added `(estimate w/o cache)` indicator on the cost line when no cache tokens were reported by the backend, signalling possible cost overestimation.
- **2026-04-27** — Added `extra_tools` and `custom_system_prompt` parameters in the `AlanCodeAgent` constructor.
- **2026-04-18** — Cache token display improvements on the Anthropic backend.
- **2026-04-18** — LiteLLM caching: switched to `cache_control_injection_points` for cleaner, backend-agnostic caching.
- **2026-04-17** — Added prompt caching for both Anthropic and LiteLLM backends (up to 4 `cache_control` breakpoints per call).
- **2026-04-17** — Improved user-message rendering in the CLI: user input is now grey, with a blank line before the assistant response.
- **2026-04-17** — `litellm` is now the default backend (was `anthropic`). Default model is now `anthropic/claude-sonnet-4-6`.
- **2026-04-17** — Removed `force_supports_*` settings. Alan now assumes capabilities are supported and surfaces the real backend error when they aren't.
- **2026-04-17** — GUI chat panel now correctly displays assistant text on session resume and synthetic error messages (both were previously silently dropped).
- **2026-04-16** — Alan Code v1.0.0 — initial public release.
